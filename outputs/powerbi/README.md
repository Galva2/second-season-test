# Power BI data package

Generated by `scripts/build_outputs.py` from the MySQL database `imdb_series`.
Encoding UTF-8 (with BOM), comma-separated, header row. Booleans are 0/1. Empty field = NULL.

The row-level files (`dim_*`, `bridge_*`, `fact_*`) contain IMDb-derived data, so they are
**not committed to git**. Run `python scripts/build_outputs.py` to regenerate them.
The `summary_*` files are small aggregates that match the numbers in the README.

## Data model (star schema)

```
dim_series (1) ──< bridge_series_genre (genre filter, many-to-many)
     │
     ├──< fact_season        (series_id)
     ├──< fact_season_pair   (series_id)
     ├──< fact_q2_pilot      (series_id, 1:1)
     └──< fact_q3_renewal    (series_id, 1:1)
```

Relationships in Power BI: `dim_series[series_id]` → each fact table's `series_id` (one-to-many, single direction).
For genre slicing, relate `bridge_series_genre[series_id]` → `dim_series[series_id]` and set the filter direction to **both**,
because a series has up to 3 genres.

## Tables

### dim_series — one row per scripted TV series (167,650)
| Column | Meaning |
|---|---|
| series_id | IMDb id (tconst) |
| title | Series title |
| start_year, end_year | IMDb years. end_year NULL = still running or unknown |
| is_ended | 1 if end_year is set and ≤ 2026 |
| genres | Original comma list (up to 3, alphabetical) |
| n_seasons_max | Highest numbered season listed (series length) |
| n_seasons_qualifying | Seasons passing the quality filter (≥ 80% episodes rated, median votes ≥ 20) |

### bridge_series_genre — one row per series per genre (251,173)
| Column | Meaning |
|---|---|
| series_id, genre | A series appears once per genre it has |

### fact_season — one row per series per numbered season 1–100 (176,251)
| Column | Meaning |
|---|---|
| season, season_year | Season number, earliest episode year |
| n_episodes, n_rated | Episodes listed / episodes with an IMDb rating |
| median_votes | Median votes per rated episode (audience proxy) |
| rating | Simple mean of episode ratings (quality proxy) |
| is_qualifying | 1 = used in the analysis. **Filter on this in most visuals** |
| is_current_year | 1 = season started in 2026 (votes still accumulating) |

### fact_season_pair — Q1: consecutive qualifying seasons (12,582)
| Column | Meaning |
|---|---|
| season_from, season_to | e.g. 1 → 2 |
| year_from, year_to, era | Years of both seasons. era = era of the later season (≤2012 / 2013-2018 / 2019-2025) |
| vote_change | votes_to / votes_from − 1 (−0.25 = lost 25%) |
| rating_change | rating_to − rating_from |

### fact_q2_pilot — Q2: ended series with a qualifying season 1 (8,252)
| Column | Meaning |
|---|---|
| pilot_rating, pilot_votes | Season 1 episode 1 (NULL if unrated) |
| s1_rating, s1_median_votes | Season 1 |
| got_season_2 | 1 if the series had a season 2 |
| s1_rating_bucket | Rating band used in the README chart |

### fact_q3_renewal — Q3: ended series with a valid season 1 → 2 pair (3,801)
| Column | Meaning |
|---|---|
| vote_change, rating_change | Season 1 → 2 |
| vote_tertile, rating_tertile | Equal thirds (1 = worst, 3 = best) |
| got_season_3 | 1 if the series had a season 3 |

## The dashboard (built in Power BI Desktop)

One page, 1280×720, on a grid (20 px margins, 16 px gaps). The `.pbix` file embeds IMDb-derived data, so it is not committed. See the screenshot in the main README.

**Layout:** title + slicers (Genre, Years aired) → 4 KPI cards → 2×2 charts.

**Measures (DAX)**

| Measure | Table | Definition | Value with no filters |
|---|---|---|---|
| Median Vote Change | fact_season_pair | `MEDIAN(fact_season_pair[vote_change])` | by transition |
| Drop at S2 | fact_season_pair | `CALCULATE([Median Vote Change], fact_season_pair[season_from] = 1)` | −24.5% |
| Share Lost Votes S2 | fact_season_pair | Share of 1→2 pairs with `vote_change < 0` (`VAR` + `CALCULATE` + `DIVIDE`) | 96.2% |
| Series Analyzed | fact_season_pair | `DISTINCTCOUNT(fact_season_pair[series_id])` | 4,552 |
| Series Pairs | fact_season_pair | `COUNTROWS(fact_season_pair)` | 12,582 |
| Audience Lost S2 | fact_season_pair | `-[Drop at S2]` (positive, for the genre bar chart) | 24.5% |
| Renewal Rate S2 | fact_q2_pilot | `AVERAGE(fact_q2_pilot[got_season_2])` | 53.8% |
| Series Count Q2 | fact_q2_pilot | `COUNTROWS(fact_q2_pilot)` | 8,252 |

Calculated column `Transition` = `season_from & "→" & season_to`, sorted by `season_from`.

**Visuals**

| Visual | Fields | Matches |
|---|---|---|
| Retention curve (line) | Transition × Median Vote Change, season_from ≤ 8 | sql/mysql/11 |
| Renewal by season 1 rating (column) | s1_rating_bucket × Renewal Rate S2, sorted by bucket | sql/mysql/21 (21a) |
| Audience vs quality (clustered column) | summary_q3: tertile (categorical) × pct_got_season_3, legend signal_name | sql/mysql/31 (31a) |
| Drop at season 2 by genre (bar) | genre × Audience Lost S2, 6 genres (decision #31) | sql/mysql/13 (raw, not era-adjusted) |

**Behaviour to know**
- The genre slicer reaches `fact_season_pair` and `fact_q2_pilot` through `dim_series` (bridge relationship set to Both). The summary_q3 chart is not filtered by slicers.
- The Years aired slicer filters `fact_season_pair` only. "Got a second season" does not change with it.
- Clicking a point on the line chart cross-filters the page. Cards that are fixed to 1→2 show blank when another transition is selected. Interactions from the line chart to those cards can be set to None (Format → Edit interactions).
- Genre values on the dashboard are raw. The README genre chart is era-adjusted, which is why Thriller ranks first here and Sci-Fi ranks first there.

## Notes for building visuals
- Medians: use DAX `MEDIAN()` on `vote_change`. Do not average percentages.
- Renewal rate: `AVERAGE(fact_q2_pilot[got_season_2])` formatted as %.
- Always show n (row count) next to a rate. Small groups are noisy.
- Votes are an audience **proxy** (self-selected IMDb users), not viewers.
